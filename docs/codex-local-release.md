# Local human validation handoff

This is the first point where Relay requires a real development machine. GitHub-side source hardening can inspect and change the repository, but it cannot prove a clean dependency install, execute the full test/build graph, run Docker or validate ChatGPT's browser.

Do not add scope during this phase. The job is to convert the current branch into evidence.

## Current hard blocker

`package-lock.json` is intentionally not fabricated through GitHub. It must be generated by npm from the real package registry, reviewed and committed before the deterministic release gate can pass.

## 1. Open the exact branch

```bash
cd /path/to/relay-webmcp
git fetch origin
git checkout build/pact-vertical-slice
git pull --ff-only origin build/pact-vertical-slice
git status --short
git rev-parse HEAD
```

Stop if the worktree is not clean.

## 2. Use the required toolchain

```bash
nvm install 22
nvm use 22
npm install --global npm@10.9.2 --no-audit --no-fund
node --version
npm --version
```

Required:

```text
Node 22.x
npm 10.9.2
```

## 3. Generate the lockfile once

```bash
npm install --package-lock-only --ignore-scripts --no-audit --no-fund
```

Before committing it, inspect the dependency graph:

```bash
git diff -- package-lock.json
node -e 'const l=require("./package-lock.json"); console.log({lockfileVersion:l.lockfileVersion, packages:Object.keys(l.packages||{}).length})'
```

The lockfile must use `lockfileVersion: 3` or newer.

Then prove that the new lockfile can install and verify the repository:

```bash
rm -rf node_modules
npm ci --no-audit --no-fund
npm run verify
```

Do not weaken a gate to make this green. Preserve the complete output of the first failing command.

When the install and verification pass:

```bash
git add package-lock.json
git commit -m "chore: lock submission dependencies"
git status --short
```

The tree must be clean again.

## 4. Run the single source release gate

```bash
npm run gate:source
```

This gate independently proves:

```text
correct branch
clean tree before and after
exact 40-character Git head
Node 22
npm 10.9.2
committed lockfileVersion >= 3
syntax of every release script
release-surface contract
fresh npm ci
all source/security/provenance gates
TypeScript
protocol and hostile tests
all four production builds
```

Machine-readable output is written to the ignored directory:

```text
.relay-artifacts/release/source-release-gate-<commit>.json
```

Do not direct gate output into tracked `evidence/` while iterating. Copy final evidence there only after the validated commit is frozen.

## 5. Failure protocol

For the first failure only:

1. Preserve the exact command, exit code, stdout and stderr.
2. Do not run broad automated rewrites.
3. Reproduce the failing command directly.
4. Fix only the confirmed blocker on `build/pact-vertical-slice`.
5. Add or strengthen a regression test.
6. Return to a clean tree.
7. Rerun `npm run gate:source`.

## 6. Deployment after source green

Continue with:

```text
docs/production-operator-runbook.md
```

The deployment contract uses:

```env
RELAY_RELEASE_SHA=<exact output of git rev-parse HEAD>
```

The full release command is:

```bash
npm run gate:release -- --env .env.deploy
```

## 7. Actual ChatGPT gate

After all four HTTPS origins pass deployment smoke, follow:

```text
docs/chatgpt-validation.md
```

Ordinary Chrome, Playwright and `?proof=1` are harness evidence, not actual ChatGPT evidence.

## Final rule

Do not merge PR #1 until all of these are real passes:

```text
source release gate
four-origin deployment gate
actual ChatGPT browser gate
three canonical rehearsals
three stale/recovery rehearsals
public video under three minutes
repository visibility requirement
```
